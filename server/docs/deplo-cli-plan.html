deplo.ai · product plan · v0.1 → v0.3

deplo CLI — production URLs, without leaving the terminal

Everything the dashboard does today — Vercel frontends and Render backends deployed into accounts the user owns, stack detection, env wiring, AI failure diagnosis, monitoring — exposed as one command. The CLI is a thin client over the existing REST API: no new orchestration, one small auth addition. It installs from a public registry on any machine and takes a brand-new user from install to a live URL without ever opening the dashboard.

Why this is cheap to build and valuable to ship

Three facts make the CLI a high-leverage move rather than a second product.

API ALREADY EXISTS

Consumer #2 of the same REST API

Deploy, status, logs, env, monitoring and analytics endpoints are live and battle-tested by the dashboard. The CLI adds zero orchestration logic.

BRAND FIT

The brand is literally a terminal

The landing page sells $ git push → URL. The CLI makes the marketing true in the medium it was promised in — and a terminal recording is the most shareable demo a dev tool can produce.

CI UNLOCK

From tool to pipeline step

npx deplo-cli deploy --wait in GitHub Actions turns deplo into a CI deployment step with exit codes — a whole new usage category for free.

OWN-ACCOUNTS STORY

Same trust model

Deploys still land in the user's own Vercel account and Render workspace. The CLI holds one deplo token — never the user's provider credentials.

Command reference

v0.1 — the core loop

CommandBehavior
deplo loginOpens the browser to deplo.in/cli-auth?port=…, signing in with GitHub if needed, and receives a token on a loopback listener. --token pastes one manually (headless boxes, CI, SSH). Stored at ~/.config/deplo/config.json, 0600.
deplo connect vercelFetches the Vercel install URL, opens it, then polls /integrations until the connection lands. --print-url for headless machines — copy the link to any browser and come back.
deplo connect renderPrompts for a Render API key (masked input, never echoed) and posts it to /integrations/render. No browser needed at all. --key for scripts.
deplo whoamiAccount, GitHub login, and a connection checklist: Vercel ✓/✗, Render ✓/✗. Tells the user exactly which connect command is still missing.
deplo / deplo deployReads the git remote of the current directory, syncs repos if it's unseen, matches it to a synced repo, triggers a deployment, and follows the live deployment log. Ends with both production URLs. Missing prerequisites trigger the matching login/connect step inline rather than an error. --yes skips confirmation.
deplo statusLatest deployment state for the current repo; --all for every project.
deplo listAll projects with status dots, stack, and URLs.
deplo logs [id]Full deployment log; keeps following while the deployment is active.
deplo openOpens the frontend URL. --api backend, --dash the deplo dashboard page for this project.

v0.2 — operate from the terminal

CommandBehavior
deplo env set K=V…Answer the waiting-for-env state without opening the browser; env ls shows detected keys (values masked, scopes shown).
deplo monitorHealth in the terminal: up/down dots, latency, 24h uptime, CPU/memory sparklines (▁▂▄▇) from the monitoring API. --watch refreshes every 30s.
deplo analyticsViews, visitors, top pages and referrers as a table; prints the insights snippet if analytics isn't set up yet.
--json everywhereMachine-readable output on every command for scripting.

v0.3 — CI mode

.github/workflows/deploy.yml
# deploy on every push to main — exit code 0/1 gates the pipeline
- run: npx deplo-cli deploy --wait --token ${{ secrets.DEPLO_TOKEN }}

On failure, --wait prints the AI diagnosis and the copy-paste fix prompt directly into the CI log, then exits non-zero.

First run on a machine that has never seen deplo

The CLI must not assume a dashboard visit ever happened. A developer who finds deplo-cli on npm gets the whole onboarding — GitHub sign-in, Vercel connect, Render key — in the terminal, and the dashboard becomes optional rather than a prerequisite.

● Deployed in 2:41 — code went in, production URLs came out.
  1. Install — no account requiredPublic npm package. npx deplo-cli runs on any machine with Node 20+; the Homebrew tap and install script cover machines without Node.
  2. deplo login — GitHub, in the browserLoopback hand-off against the existing /auth/github OAuth flow. First-time users sign up in the same step — there is no separate "create an account" path to document.
  3. deplo connect vercel — OAuth, then pollUses the live /integrations/vercel/install-url endpoint. The CLI never sees the Vercel token; it just polls /integrations until the server reports connected: true.
  4. deplo connect render — masked pasteRender has no OAuth app, so the key is pasted once and posted to /integrations/render, where it's encrypted server-side exactly as the dashboard does it. Never written to the CLI config file.
  5. deplo — sync and shipRepos sync on demand, the git remote is matched, and the deploy runs. Any missing prerequisite from steps 2–4 is offered inline instead of failing.
Never a dead end: every browser step has a headless twin — login --token, connect vercel --print-url, connect render --key — so SSH sessions, devcontainers, WSL and CI runners are first-class rather than unsupported.

Auth — the only real server work

Browser JWTs expire in 7 days; a CLI needs revocable long-lived tokens. Both phases now ship in v0.1 — the hand-off is what makes the CLI usable by someone who has never opened the dashboard, so it is no longer a v0.3 nicety.

PHASE 1 · BUILT

Token primitive

CliToken table (SHA-256 hashed, named, revocable, last-used tracked), CliTokenService, POST/GET/DELETE /cli-tokens, and auth middleware that resolves a dpl_… bearer instead of verifying a JWT. Additive migration, already on feat/deplo-cli.

PHASE 2 · SHIPS WITH v0.1

Browser hand-off

deplo login starts a loopback listener and opens deplo.in/cli-auth?port=…. The page signs the user in with GitHub if needed, mints a token named after the machine, and redirects to 127.0.0.1:<port>. One new client page; no new API.

FALLBACK · SHIPS WITH v0.1

Paste token

Dashboard → Settings → "Create CLI token" for machines with no browser, plus deplo login --token and the DEPLO_TOKEN env var for CI. Same endpoint, different entry point.

HARDENING

Before the package is public

Rate-limit token creation, bind the hand-off to a single-use nonce with a short TTL, only ever redirect to a loopback address, and show token name + lastUsedAt in Settings so a leaked machine token is obvious and revocable.

Security posture: the CLI stores one deplo token, never provider credentials. Vercel OAuth tokens and Render API keys stay encrypted server-side, exactly as today — connect render posts the key straight through and keeps nothing on disk.

Distribution — how anyone gets it

Nothing here needs anyone's permission: npm and a Homebrew tap are both self-publish. The only gated channel is Homebrew's core repository, which is a later milestone rather than a launch step.

install — pick one
$ npx deplo-cli login                          # no install, always latest
$ npm i -g deplo-cli                           # then just: deplo
$ brew install deplo-ai/tap/deplo              # macOS + Linuxbrew, no Node needed
$ curl -fsSL https://deplo.in/install.sh | sh  # CI images, bare Linux
ChannelWhat it takes to ship itWhen
npmPublish deplo-cli public and unscoped, bin: { deplo }, files: ["dist"], engines.node >= 20, shebang on the entry file. Release from CI with an automation token and --provenance so the npm page shows a verified build.v0.1
Homebrew tapA public repo named homebrew-tap under the deplo org with Formula/deplo.rb. No review, live on push. Formula points at the platform binaries attached to the GitHub Release; a release job recomputes the sha256 and bumps the tap automatically.v0.2
install.shDetects OS/arch, downloads the matching release binary, drops it in ~/.local/bin. The channel that works on a Linux CI image with no Node and no Homebrew.v0.2
Standalone binariesbun build --compile (or Node 22 SEA) for darwin-arm64, darwin-x64, linux-x64, linux-arm64, win-x64, attached to each GitHub Release. Removes the Node prerequisite and kills npx cold-start entirely — this is what the tap and the install script both consume.v0.2
Scoop / WinGetSame Windows binary, one manifest each. Worth doing only once Windows usage actually shows up — until then npx deplo-cli covers it.later
homebrew-coreThe plain brew install deplo namespace. Requires passing Homebrew's notability bar and a maintainer review, so it is a traction milestone, not a launch task. The tap keeps working either way.later
Release pipeline (one workflow, tag-triggered): build → cross-compile the five binaries → GitHub Release → npm publish --provenance → bump the tap formula. Every channel then serves the same version from the same commit, and a release is a git tag rather than a checklist.
Public prerequisites on the server side: PUBLIC_URL and the Vercel integration's redirect URL must point at production (the install-url endpoint already 503s without it), the /cli-auth page has to be live on the marketing domain, and the API needs to answer from the public origin — the CLI is not a browser, so CORS is irrelevant, but rate limits and clear 4xx bodies now face strangers instead of the dashboard.

Architecture & packaging

deplo-ai/cli
cli/
├── src/
│   ├── commands/        login · connect · whoami · deploy · status · logs · list · env · monitor · open
│   ├── api.ts           typed client for www.deplo.in/api/v1 (same contracts as the dashboard)
│   ├── auth.ts          token store — ~/.config/deplo/config.json, 0600
│   ├── handoff.ts       loopback listener for browser login — 127.0.0.1 only, single-use nonce
│   ├── git.ts           cwd git remote → synced repo match
│   └── ui.ts            spinners · status glyphs · NO_COLOR + non-TTY fallbacks
├── install.sh           OS/arch detect → release binary → ~/.local/bin
└── package.json         name: "deplo-cli" · bin: { "deplo": "dist/index.js" }

Node 20 + TypeScript, commander for commands, @clack/prompts for the interactive bits, picocolors. Deliberately light so npx cold-start stays fast. The API base URL defaults to production and is overridable with DEPLO_API_URL, so the same published binary works against staging or a local server without a rebuild. Published to npm at v0.1; binaries, the Homebrew tap and install.sh follow in v0.2.

Naming (verified on npm): deplo is taken and the @deplo scope is claimed — deplo-cli is free. The installed command is still deplo; docs must always say npx deplo-cli, never npx deplo (that runs a stranger's package). Homebrew has no such collision — taps are namespaced, so the formula is plainly deplo, which is a second reason to ship the tap early.

UX principles

PrincipleIn practice
Deliver the brand promiseThe deploy output ends exactly like the landing page's terminal strip: URLs with green dots. The film, the site, and the CLI show the same moment.
Failures teachCause → file → fix → AI prompt, in that order — the terminal version of the failure email.
Never trap a scriptEvery prompt has a flag; --json and meaningful exit codes everywhere; NO_COLOR and dumb-terminal fallbacks respected.
No machine is second-classEvery browser step has a headless twin, and no command assumes the dashboard was ever opened. If a step can't run here, the CLI prints the URL and waits rather than failing.
Missing setup is a prompt, not an errorNot logged in, no Vercel, no Render, repo unsynced — each resolves inline with the next command offered, so a first run never ends in a wall of red.
Color is state, not decorationGreen = live, red = failed, cyan = URLs/actions, violet = AI content. Nothing else is colored.
