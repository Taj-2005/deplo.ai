deplo CLI — production URLs, without leaving the terminal

Everything the dashboard does today — Vercel frontends and Render backends deployed into accounts the user owns, stack detection, env wiring, AI failure diagnosis, monitoring — exposed as one command. The CLI is a thin client over the existing REST API: no new orchestration, one small auth addition.

Why this is cheap to build and valuable to ship

Three facts make the CLI a high-leverage move rather than a second product.

API ALREADY EXISTS

Consumer #2 of the same REST API

Deploy, status, logs, env, monitoring and analytics endpoints are live and battle-tested by the dashboard. The CLI adds zero orchestration logic.

BRAND FIT

The brand is literally a terminal

The landing page sells $ git push → URL. The CLI makes the marketing true in the medium it was promised in — and a terminal recording is the most shareable demo a dev tool can produce.

CI UNLOCK

From tool to pipeline step

npx deplo-cli deploy --wait in GitHub Actions turns deplo into a CI deployment step with exit codes — a whole new usage category for free.

OWN-ACCOUNTS STORY

Same trust model

Deploys still land in the user's own Vercel account and Render workspace. The CLI holds one deplo token — never the user's provider credentials.

Command reference

v0.1 — the core loop

CommandBehavior
deplo loginPaste a CLI token from the dashboard (Settings → CLI). --token flag for scripts. Stored at ~/.config/deplo/config.json with 0600 permissions.
deplo / deplo deployReads the git remote of the current directory, matches it to a synced repo, triggers a deployment, and follows the live deployment log in the terminal. Ends with both production URLs. --yes skips confirmation.
deplo statusLatest deployment state for the current repo; --all for every project.
deplo listAll projects with status dots, stack, and URLs.
deplo logs [id]Full deployment log; keeps following while the deployment is active.
deplo openOpens the frontend URL. --api backend, --dash the deplo dashboard page for this project.

v0.2 — operate from the terminal

CommandBehavior
deplo env set K=V…Answer the waiting-for-env state without opening the browser; env ls shows detected keys (values masked, scopes shown).
deplo monitorHealth in the terminal: up/down dots, latency, 24h uptime, CPU/memory sparklines (▁▂▄▇) from the monitoring API. --watch refreshes every 30s.
deplo analyticsViews, visitors, top pages and referrers as a table; prints the insights snippet if analytics isn't set up yet.
--json everywhereMachine-readable output on every command for scripting.

v0.3 — CI mode

.github/workflows/deploy.yml
# deploy on every push to main — exit code 0/1 gates the pipeline
- run: npx deplo-cli deploy --wait --token ${{ secrets.DEPLO_TOKEN }}

On failure, --wait prints the AI diagnosis and the copy-paste fix prompt directly into the CI log, then exits non-zero.

When a deploy fails

The same Groq diagnosis that powers the failure email renders in the terminal — cause, affected file, and a prompt the developer can paste into Cursor or Claude Code.

~/projects/my-app
✗ Deployment failed — Render build exited 254

CAUSE          build ran at the repo root — no package.json there
AFFECTED FILE  server/package.json
FIX            set the service root to server/ and redeploy

AI FIX PROMPT  (copy into Cursor / Claude Code / Copilot)
│ My Express server in server/ fails to deploy with exit 254.
│ Verify server/package.json has a valid start script and the
│ app listens on process.env.PORT…

$ deplo deploy --retry

Auth — the only real server work

Browser JWTs expire in 7 days; a CLI needs revocable long-lived tokens.

PHASE 1 · SHIPS WITH v0.1

Paste token

Dashboard → Settings → "Create CLI token". New CliToken table (hashed, named, revocable, last-used tracked) + auth middleware accepting it. Additive migration, ~1 day.

PHASE 2 · v0.3

Browser hand-off

deplo login opens deplo.in/cli-auth?port=…; the already-signed-in browser approves and redirects to localhost with the token. No copy-paste.

Security posture: the CLI stores one deplo token, never provider credentials. Vercel OAuth tokens and Render API keys stay encrypted server-side, exactly as today.

Architecture & packaging

deplo-ai/cli
cli/
├── src/
│   ├── commands/        login · deploy · status · logs · list · env · monitor · open
│   ├── api.ts           typed client for www.deplo.in/api/v1 (same contracts as the dashboard)
│   ├── auth.ts          token store — ~/.config/deplo/config.json, 0600
│   ├── git.ts           cwd git remote → synced repo match
│   └── ui.ts            spinners · status glyphs · NO_COLOR support
└── package.json         name: "deplo-cli" · bin: { "deplo": "dist/index.js" }

Node 20 + TypeScript, commander for commands, @clack/prompts for the interactive bits, picocolors. Deliberately light so npx cold-start stays fast. Published to npm; Homebrew tap later.

Naming (verified on npm): deplo is taken and the @deplo scope is claimed — deplo-cli is free. The installed command is still deplo; docs must always say npx deplo-cli, never npx deplo (that runs a stranger's package).
